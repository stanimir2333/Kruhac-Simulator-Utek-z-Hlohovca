# Kruháč Simulator: Útek z Hlohovca

A GTA-style driving game that runs entirely in the browser, set in **Hlohovec,
Slovakia** — rendered 1:1 from real OpenStreetMap data, on real terrain.

You start stuck in a traffic jam south of the city. Escape through roundabouts,
along Route 513, over the Váh bridge and out of town, with a passenger who has
opinions about your driving. The in-game UI is Slovak.

## Quick start

```bash
npm install
npm run dev        # http://localhost:5173
```

That's it — there is no server, no database and no build step to run the game.
Vite only exists for hot reload during development.

| Script | What it does |
| --- | --- |
| `npm run dev` | Dev server on `http://` (sends `Cross-Origin-Opener-Policy: same-origin`) |
| `npm run build` | `dist/index.html` — JS + CSS inlined into **one** file (~1 MB), plus `dist/data` and `dist/audio` |
| `npm run build:portable` | Inlines the audio too → ~25 MB HTML that stalls the parser. Avoid. |
| `npm run preview` | Serve the built `dist/` |

Requires Node >= 18. The game itself needs no Node at runtime — `dist/` is static
files.

### Deploying

There is no build step on the deploy side. GitHub Pages serves the **repository
root**, so `index.html` runs straight from `main` with no CI, and `three` is
resolved from unpkg via an import map in `index.html`. Nothing is generated at
deploy time — everything the game loads is committed (see
[Data sources](#data-sources--attribution)).

### Cheats

Typed GTA-style, all caps:

`NOCLIP` · `WARPZAMOK` · `WARPURBANEK` · `WARPBRIDGE` · `WARPSTATION` ·
`WARPPETER` · `FIXCAR` · `TURBO`

`NOCLIP` releases the camera entirely — `W`/`S` fly forward and back, `A`/`D`
turn, `Space` goes up, `Shift` goes down, `E` sprints. Cheat codes suppress
single-key shortcuts while a prefix is being typed, so press those keys alone
when you test a shortcut.

## Features

- **Real city, real terrain.** 5.3 × 5.1 km of Hlohovec at 1:1 scale — 6 181
  buildings, 852 road centrelines, the Váh river, railway, canals, parks.
- **Real heightmap.** SRTM elevation data resampled onto the 257 × 257 terrain
  grid, so the ground actually slopes from the floodplain up to the Little
  Carpathians (130 m → 308 m above sea level).
- **Traffic AI** that brakes for you, merges, and routes over the road graph.
- **Physics** with suspension sampling at four wheels, so cars pitch and roll
  over terrain. Engine heat, driver stress, tyre grip and a drift mini-game.
- **8-station radio** and dynamic sun shadows, bloom, and planar water
  reflections.
- **Procedural fallback for every texture** — the game never shows a black
  surface, even if an image fails to load.

## How the map works

The city is not decorative. One world unit = one metre, and everything is
projected from real OSM data with this linear projection:

```
x = (lon - 17.8136414) * 73876.98
z = -(lat - 48.4212428) * 110539.70
```

```
OSM export (.osm)
   │
   ├── public/data/mapData.json ........ hand-authored gameplay layers
   │                                        (route, missions, roundabouts,
   │                                         bridge, labels, street names)
   ├── public/data/osmExtra.json ....... generated by tools/gen_osm_extra.py
   │                                        (6 181 buildings, tree positions,
   │                                         elevation survey points)
   └── assets/terrain/hlohovec_dem.png . SRTM elevation, 257x257, 50 kB
                                            (built by tools/build_dem.py)
   │
   ▼
src/world/mapData.js — loadWorld() merges the layers into S.osm
   │
   ▼
height.js (terrain) · roads.js · water.js · buildings.js · nature.js
```

`mapData.json` is **generated** — `prebuild` rewrites it from a legacy monolith.
Anything hand-added to it would be silently destroyed on the next build, which
is why the new OSM layers live in their own file that the extractor cannot
touch.

### Regenerating the map assets

```bash
python3 tools/build_dem.py         # SRTM tiles -> assets/terrain/hlohovec_dem.{png,json}
python3 tools/gen_osm_extra.py     # OSM export -> public/data/osmExtra.json
python3 tools/preview_terrain.py   # offline: height histogram + key places (--ascii)
```

Both generators are idempotent and only write their own outputs. Note that
`gen_osm_extra.py` unions the new export with points from the existing layers
that fall outside the export's bounding box, so the result is always a superset —
no trees or buildings are ever silently lost.

### Height data

The terrain base is an SRTM elevation raster. OSM only carries 10 surveyed
`ele=` points in the whole area, so they are used as a **clamped correction on
top of** the DEM rather than as the height model itself — they disagree with
SRTM by up to 30 m at some spots, and forcing them exactly would deform the
terrain.

The DEM is stored as two 8-bit channels (high byte in red, low byte in green),
because `canvas.getImageData()` is 8-bit only — a 16-bit PNG would degrade to
0.7 m per step in game and the car would visibly jitter on flat ground.

### Water

OSM's `waterway=river` geometry for this stretch of the Váh is very coarse: some
segments are 819 m long, and one end of the way runs 1.2 km south up the
Carpathian hillside. `pruneWaterLines()` filters water lines against the DEM —
a point more than a few metres above the local valley floor is treated as an OSM
error — and keeps the longest continuous run, which is the real channel.

## Project structure

```
index.html              slim shell: all HUD markup + the three.js import map
src/main.js             the only entrypoint — boot order lives here
src/core/               engine (rAF + FPS cap), input, async loader, state
src/world/              heightmap, ground, roads, water, buildings, vegetation,
                        textures, sky, labels
src/physics/vehicle.js  vehicle model + world collision
src/ai/traffic.js       civilian traffic AI
src/game/               missions, drift, cheats, the passenger
src/ui/                 HUD, dashboard, minimap, menus, settings
src/audio/              radio + procedural SFX
assets/textures/        PBR texture sets (see README there for the rules)
assets/terrain/         SRTM heightmap
public/data/            map layers
public/audio/           8 radio stations (23 MB, committed on purpose)
tools/                  offline generators and checkers
```

Architecture is **factory functions with dependency injection** — every module
exports `createX()` / `updateX()` and receives the mutable state object `S`
rather than importing it from `main.js`. There are no classes in `src/`.

## Verification

No test suite. What exists and passes:

```bash
python3 tools/leak-check.py        # undefined-identifier scan (src/world/ only)
python3 tools/check_textures.py    # texture slots vs assets/ (exit 1 on drift)
deno check --no-remote src/*.js    # parse + type check, no Node needed
deno lint src/                     # unused vars etc. (no repo config, 43 known)
```

Beyond that, load the game and read the console: `[map]`, `[DEM]`, `[boot]`
(per-step timings in ms), `[VODA]`, and the `blds` / `vegetácia` counts.

`#fps` in the corner reports `FPS · N DC · Nk tri` from `renderer.info` — use
that before and after any change instead of guessing at performance.

## Known issues

- **The mission route never crosses the Váh.** The closest the route comes to the
  real river axis is 975 m; the `bridge` coordinate sits on a hillside. The route
  and bridge positions were derived from the same coarse OSM river geometry
  described above, so the "most ponad Váh (362 m)" chapter plays as a viaduct over
  a slope. Fixing this means redesigning the route, not the terrain.
- ~10 FPS under software WebGL in headless Chromium. That is a software-rasteriser
  number, not a performance measurement.
